## 修复内容（摘要）

- **不同人的记忆彼此隔离。** 模型曾在工具调用中指定另一个人的 `subject`，从而读取、写入或删除其记忆；现在宿主程序的绑定始终优先。
- **删除确实彻底删除。** `erase` 曾把对方的话留在词向量中心里，查询词也会被学习。现在查询不教任何东西，每个向量都记录它教过的检索词，`erase` 和 `purge` 会精确收回这些内容（在 CLI 中也是如此，无需分词器）。较早构建生成的文件会在打开时修复。`Mneme.erase` 还会移除心情。
- **导入不会丢数据。** 导入曾可能让某个键没有对应的有效笔记、保留重复文本、把对方的大多数较早笔记当作“重复”隐藏起来、因一行异常而整体失败，或在执行两次时让心情时间线翻倍。现在导入逐行遵守与写入相同的规则。
- **并发。** 第二个进程写入时曾立即失败（“database is locked”）；两个进程同时打开新文件会崩溃（40 次试验中有 31 次）；失败的 `begin` 曾让写锁保持占用；一条笔记在生成向量时被删除，或同时生成向量两次，曾破坏词向量中心的账；打开时的账检查可能与另一个写入进程发生竞争；两个提示词同时执行可能把同一条心情消息告诉模型两次。均已修复；压力测试套件针对同一个文件运行线程、进程和协程。
- **异常输入。** 孤立代理项、控制字符、NaN 和无穷数、以毫秒表示的时间、诸如 0001-01-01 的日期、本该是文本处的 `None`、嵌套数千层的 JSON、通过 MCP 传入的无效 UTF-8、以 `{"role", "content"}` 给出的聊天消息、以生成器给出的一轮对话。现在每种情况都会被清理、以普通的 `ValueError`/`TypeError` 拒绝，或被正确读取；都不会使宿主程序崩溃或终止 MCP 服务器。
- **语言和文本。** 含非 ASCII 字母、组合标记、连接符、希伯来语和阿拉伯语元音符号、土耳其语 İ、排版撇号和德语 ß 的词语都能被正确分词和比较；西里尔字母、希腊字母、阿拉伯字母、希伯来字母、天城文和泰文在统一语言层各自拥有自己的文字系统。
- **日期。** 写下的日期是对方所在的那一天，而不是服务器所在的那一天；日期解析器能在跨新年时选对年份，对于计划则选下一个这样的日子；更长数字中的数字不会被当作日期。
- **失败的服务。** 一个格式错误的条目，或一个失败的写入进程，不再导致记笔记丢失；阻塞的写入进程不再冻结事件循环；配置错误的服务会休息，而不是在每次回忆时被询问两次；“没有聊天模型”不再计为失败；模型拒绝为某条笔记写译文不再阻塞其他笔记，服务中断也不再标记笔记。
- **结构。** 存储就是文件本身；每种行只有一个所有者；词向量中心的账位于一个模块（`meaning/ledger.py`）中；写笔记的规则集中在一个函数（`note_fields`）里，所有入口都使用它；各层重复的粘合代码位于 `providers.py` 中；记笔记只负责构建提示词和读取回复；依赖关系单向；展示给对方的每个词都在 `i18n` 中；三个可选的层可以被删除，并由一个测试和一个 CI 任务检查。

| Luna 的心情变化很少被告诉模型 | 每层各用一个阈值 | `MoodSettings.thresholds`，`{"luna": 0.45}`，放在 `threshold`（0.6）旁边；每次变化先注明是哪个层的置信度起了作用。这个值要等下次部署之后再测量。 |
| 两段短文本未加标注就发给了模型 | 给记笔记的模型的列表加标注；保留原话；告诉模型该有什么情绪 | 记笔记的模型收到的已知笔记列表被标为数据；心情消息保留对方的原话，并以一句直白的提示结尾（“值得庆祝的事：你感到开心。”） |
| `language=` 只接受语言名 | 也接受 `Unify` | `memory_language=` 接受语言名、宿主程序自己的 `Unify`，或 None |
| 参数名太相似 | 改名 | `display_language`、`memory_language`、`companion_name`、`user_name`（CLI 里为 `--display-language`、`context --user-name`） |
| 一个模块身兼两职 | 拆开 | 向量服务放在 `meaning/embedders.py` |
| 各种文字系统混在一起 | 修（人们会混用语言） | 汉字、假名和谚文被区分开来，另外约 25 种文字系统能被识别，一段文本中若有两成以上是其他文字系统就翻译，这样混用的句子也…… |

| 回忆会扫描每一条笔记 | 从容应对很长的历史 | 检索词索引（`note_terms`），最多 1,000 条候选笔记做完整打分，意思只在 5,000 条笔记的语义窗口内计算，清理分步进行，每人有效笔记上限 50,000 条：在 Raspberry Pi 5 上，100,000 条笔记的回忆耗时 50–400 ms |
| 彻底删除后仍留有通用学习 | 这是特性，不是限制 | 已在文档中说明这是设计使然 |

## 仍然待解决的问题

每一条都说明：它是什么、目前要付出什么代价、在此期间可以怎么做，以及要修复它需要做什么。

**1. 两个进程训练同一个微型判断模型** 会互相覆盖对方保存的内容：学到的会丢失，但不会损坏数据。
一个文件对应一个伴侣（推荐的配置：五个伴侣、五个文件）就能避免这种情况。

**2. 两个宿主程序用不同的分词器打开同一个文件**（一个开着 jieba，另一个关着）会不断重建对方的检索词索引，
词向量中心也会从头开始；只会花时间，从不影响正确性。不值得修补。

**3. 时间范围是 1970 年到 3000 年。** 关于 1970 年之前事物的笔记会把年份写在文本里。优先级很低。

**4. 重置之后会有一段时间比较慢。** 换了分词器之后，第一次回忆会为该对象的历史建一次索引
（约每 100,000 条笔记 9 秒），并且每次回忆都会以每 256 条笔记为单位重新教一遍词向量中心。可以接受。

**5. "意思"只在一个窗口内查找。** 有效笔记超过 5,000 条后，"意思"只比较最有价值的 5,000 条
（先比持久的，再比最新的）；一条正在淡去的旧笔记要靠它的词来找，而不是靠"意思"。
`semantic_window` 决定这个窗口的大小。

**6. 没有静态加密**，而且 CLI 的帮助只有英文（中文 README 说明了它的用法）。不值得修补。

## 设计如此

**执行 `erase` 后还剩下什么。** `Mneme.erase` 会删除与某个对象有关的每一行，
以及其笔记教给词向量中心的内容。微型判断模型会以不带文本的哈希词特征形式，
保留从所有人（包括该对象）的一轮轮对话中学到的东西：伴侣的一般判断，
以及对方的经历在朋友搬走后仍留存下来的方式。如果宿主程序哪天需要，
`mneme-llm micro --reset` 会将其重置。

**笔记可以包含什么内容。** 笔记会在一段声明其内容为数据的标头下到达模型，
每条一行；每个面向模型的提示词都会说明其输入是数据；模型仍可能遵循写在笔记里的指令，
而用户可能恰恰希望如此。宿主程序如果不想要这种效果，会在 `remember` 之前过滤。
对方自己调用 `remember` 时，也不会对机密内容做过滤。

## 从 GitHub 上的构建升级

**先停止旧进程。** 最早推送到 GitHub 上的代码所写出的文件会自行打开并升级：
缺失的列和检索词索引会被补上，笔记会在首次使用时建立索引，
可能含有检索词的词向量中心会被重置并重新学习。仍在运行旧代码的
进程会在没有账、也没有索引的情况下继续写入，因此它的改动在每次
打开时都会被再次修复，直到该进程停止。whale_chan 应当在新版本上
重启，而不是与新版本并行运行。

**API 已有变动**（见 CHANGELOG 中的“Changed from the code first pushed to
GitHub”）。whale_chan 插件已经同步更新；其他针对那次推送的构建编写的
代码需要做同样的重命名。
