## 修复内容（摘要）

- **不同人的记忆彼此隔离。** 模型曾在工具调用中指定其他人的 `subject`，从而读取、
  写入或删除其记忆；现在宿主程序的绑定始终优先。
- **删除就是彻底删除。** `erase` 曾在词向量中心里留下对方说过的词，查询词也会被
  学习进去。现在查询不教任何东西，每个向量都会记录它教过的检索词，`erase` 和
  `purge` 会精确收回这些内容（通过 CLI 也一样，无需分词器）。旧版本构建出的文件
  在打开时会被修复。`Mneme.erase` 也会一并删除心情。
- **导入不会丢数据。** 导入曾可能让某个键没有对应的有效笔记、保留重复的文本、
  把一个人大部分较早的笔记当作“重复”隐藏起来、因一行异常数据而整体失败，或者
  在执行两次时让心情时间线翻倍。现在导入与写入遵循同样的规则，逐行处理。
- **并发。** 第二个进程写入时会立刻失败（“database is locked”）；两个进程同时
  打开新文件会崩溃（40 次试验中有 31 次）；`begin` 失败后写锁仍被持有；笔记在
  生成向量时被删除，或同时被生成两次向量，会破坏词向量中心的账；打开时的账检查
  可能与另一个写入进程竞争；两个提示同时运行可能把同一条心情消息告诉模型两次。
  以上均已修复；压力测试会在同一个文件上运行线程、进程和协程。
- **异常输入。** 孤立的代理项、控制字符、NaN 和无穷大、以毫秒表示的时间、诸如
  0001-01-01 的日期、本该是文本却出现 `None`、嵌套几千层的 JSON、通过 MCP 传入的
  非法 UTF-8、以 `{"role", "content"}` 给出的聊天消息、以生成器给出的一轮对话。
  现在每种情况都会被清理、以普通的 `ValueError`/`TypeError` 拒绝，或被正确读取；
  没有一种会让宿主程序崩溃或让 MCP 服务器结束。
- **语言与文本。** 含非 ASCII 字母、组合标记、连接符、希伯来语和阿拉伯语元音符号、
  土耳其语 İ、排版撇号和德语 ß 的单词都能被正确分词和比较；西里尔文、希腊文、
  阿拉伯文、希伯来文、天城文和泰文在统一语言层各自拥有自己的文字。
- **日期。** 写入的日期按对方所在的那一天算，而不是服务器的那一天；日期解析器在
  跨新年时能选对年份，对于计划则取下一个这样的日子；更长数字中的数字不会被当作
  日期。
- **出错的服务。** 单个格式错误的条目，或失败的写入进程，不再导致记笔记丢失；
  阻塞的写入进程不再冻结事件循环；配置有误的服务会进入休息，而不是在每次回忆时
  被询问两次；“no chat model” 不再被计为失败；模型拒绝为某条笔记写译文时，不再
  阻塞其他笔记，服务中断也不再给笔记打标记。
- **结构。** 存储只有文件本身；每种行只有一个所有者；词向量中心的账集中在一个模块
  （`meaning/ledger.py`）；写笔记的规则集中在一个函数（`note_fields`）里，所有入口
  都使用它；每一层重复的粘合代码集中在 `providers.py`；记笔记只负责构建提示和读取
  回复；依赖单向指向；展示给对方的每一个字都在 `i18n` 里；三个可选的层可以被删除，
  并有测试和一项 CI 任务对此进行检查。

## 尚未解决的问题

每一项说明它是什么、当前的代价是什么、眼下能怎么办，以及修复它需要做什么。

**1. 两个进程同时教一个微型判断模型**会互相覆盖对方的保存结果：学到的内容会丢失，但不会损坏数据。一个文件
只对应一个伴侣（推荐的做法：五个伴侣、五个文件）即可避免。

**2. 两个分词器设置不同的宿主程序共用一个文件**（一个开着 jieba，另一个关着）会不断重建对方的检索词索引，
词向量中心也会从头算起；这只耗费时间，从不影响正确性。不值得修补。

**3. 时间范围是 1970 年到 3000 年。** 关于 1970 年之前事情的笔记会把年份写在文本里。优先级很低。

**4. 重置后会有一段时间变慢。** 更换分词器之后，第一次回忆会为对方的历史建立一次索引（每 100,000 条笔记
约 9 秒），并且词向量中心会按每次回忆 256 条笔记重新学习。可以接受。

**5. "意思"只在语义窗口内查找。** 有效笔记超过 5,000 条时，"意思"会比较最有价值的 5,000 条（先比长期
保留的，再比最新的）；一条正在淡去的旧笔记只能靠它的词找到，而不是靠"意思"。`semantic_window` 设置窗口
的大小。

**6. 数据存储时不加密**，而且 CLI 的帮助只有英文（中文 README 解释了它的用法）。不值得修补。

## 设计使然

**执行 `erase` 之后仍会保留的内容。** `Mneme.erase` 会删除与对方有关的
所有行，以及对方的笔记教给词向量中心的内容。微型判断模型会以不含文本的
哈希词特征，保留从所有人（包括对方）的对话中学到的东西：伴侣的一般判断，
以及朋友搬走后一个人的经历仍留存下来的方式。如果宿主程序有此需要，
`mneme-llm micro --reset` 会让它从头开始。

**笔记中可能包含什么。** 笔记会每行一条，在标明这些内容是数据的标题下
到达模型；每个面向模型的提示词都会说明其输入是数据。模型仍能遵循写在
笔记里的指令，而对方可能正希望如此。不希望出现这种情况的宿主程序会在
`remember` 之前进行过滤。对方自己发起的 `remember` 调用也不会针对机密信息
进行过滤。

## 从 GitHub 上的构建升级

**先停掉旧进程。** 最早推送到 GitHub 的代码所写出的文件，能够自行打开并升级：
缺失的列和检索词索引会被补上，笔记在首次使用时建立索引，可能含有查询词的
词向量中心会被重置并重新学习。仍在运行旧代码的进程，在写入时既没有账也没有
索引，因此它的改动在每次打开时都会被再次修复，直到该进程停止。whale_chan 应当
重启到新版本上，而不是与新版本并行运行。

**自那次推送以来，API 已经变了**（见 CHANGELOG 中的
"Changed from the code first pushed to GitHub"）。whale_chan 插件已经更新；
其他针对推送版本编写的代码，也需要做同样的重命名。
