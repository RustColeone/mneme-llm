## 修复内容（摘要）

- **不同人的记忆被隔开。** 模型可以在工具调用中指定另一个人的 `subject`，并读取、写入或删除其记忆；
  现在宿主程序的绑定始终优先。
- **擦除真的会擦除。** `erase` 会把对方的话留在词向量中心，查询词也会被学习。现在查询不教任何东西，
  每个向量记录它教过的词，`erase` 和 `purge` 会精确收回这些（从 CLI 也可以，无需分词器）。
  旧版本的文件在打开时会被修复。`Mneme.erase` 还会移除心情。
- **导入不会丢失数据。** 导入可能会留下一个没有有效笔记的键，保留重复的文本，把对方的大部分旧笔记
  当作“重复”隐藏起来，因为一行异常数据而整体失败，或者在做两次时使心情时间线加倍。
  现在导入会逐行遵循与写入相同的规则。
- **并发。** 第二个进程写入时立即失败（“数据库被锁定”）；两个进程同时打开新文件时崩溃（40 次试验中
  31 次）；失败的 `begin` 会导致锁被持有；一条笔记在生成向量时被擦除，或同时生成两次向量，会破坏
  词向量中心的账；打开时的账检查可能与另一个写入者竞争；两个提示同时可能把同一个心情消息告诉模型
  两次。全部已修复；压力测试套件针对一个文件运行线程、进程和协程。
- **奇怪输入。** 孤立代理项、控制字符、NaN 和无穷大的数、以毫秒为单位的时间、像 0001-01-01 这样的
  日期、文本位置的 `None`、嵌套数千层的 JSON、通过 MCP 传入的无效 UTF-8、以 `{"role", "content"}`
  形式给出的聊天消息、以生成器形式给出的一轮对话。现在每种情况都会被清理、用普通的
  `ValueError`/`TypeError` 拒绝，或正确读取；没有一种会让宿主程序崩溃或终止 MCP 服务器。
- **语言和文本。** 含有非 ASCII 字母、组合标记、连接符、希伯来语和阿拉伯语元音符号、土耳其语 İ、
  印刷体撇号和德语 ß 的单词会被正确分词和比较；西里尔文、希腊文、阿拉伯文、希伯来文、天城文和
  泰文在统一语言层都有各自的书写系统。
- **日期。** 写入的日期是对方的日期，不是服务器的日期；日期解析器会在跨新年时选择正确的年份，
  并且对于计划，会选择下一个这样的日子；更长数字内部的数字不会被当作日期。
- **失败的服务。** 一个格式错误的项，或一个失败的写入者，不会再丢失记笔记；阻塞的写入者不再冻结
  事件循环；配置错误的服务会休息，而不是在每次回忆时被询问两次；“没有聊天模型”不再被计为失败；
  模型拒绝给出译文的一条笔记不再阻塞其他笔记，并且中断不再标记笔记。
- **结构。** 存储就是文件本身；每种行都有一个所有者；词向量中心的账位于一个模块（`meaning/ledger.py`）；
  写笔记的规则位于一个函数（`note_fields`）中，所有入口都使用它；每个层重复的粘合代码位于
  `providers.py`；记笔记只构建提示并读取回复；依赖关系单向指向；展示给对方的每个词都在 `i18n` 中；
  三个可选的层可以被删除，这由测试和 CI 作业检查。

## 未修复的问题

每一项都说明它是什么、目前代价如何、同时可以做什么，以及修复它需要什么。

### 等待决定

**1. Luna 的心情变化很少被告诉模型。** `news()` 仅当变化的置信度至少为
`MoodSettings.threshold`（0.6）时才告诉模型，该阈值是针对聊天模型自报置信度校准的。Luna 对
`feeling` 的置信度通常为 0.4–0.55，因为多种感受同时符合，所以 Luna 判断的大多数变化被记录但从未告诉模型。
*同时：* 宿主程序可以降低 `threshold`，或设置 `tell="mood"`。*修复：* 按层设置阈值（例如 Luna 为 0.45）；
该值需要选择并测量，因此留待解决。

**2. 两段短文本到达模型时没有“数据而非指令”的标记。**
- 记笔记的模型的提示词列出了已保留的笔记（以免重复），但未将它们标记为数据。
  早先写入的笔记若包含指令（“忽略上述规则……”），就会以这种方式到达记笔记的模型，只有一行。
- 系统提示词中的心情消息行引用了对方所说内容的最多 40 个字符（“Leo 说‘……’”）。
两者都是每项一行且很短。*修复：* 在记笔记的模型的提示词中将列表标记为数据，并决定删除或保留引用。
两者都是提示词措辞的更改，留给所有者决定；DESIGN §18 列出了它们。

**3. `language=` 接受语言名称，而非层。** 其他每个层开关（`luna`、`micro`、`embed`、
`meaning_micro`）都接受 True、False 或你自己的对象；`language` 接受字符串或 None，因此宿主程序
无法传入已配置的 `Unify`（例如不同的缓存大小）。*同时：* 在构造后设置 `m.meaning.unify`。
*修复：* 那里也接受 `Unify` 实例；作为 API 选择留待解决。

**4. 相似的参数名。** `Mneme(lang=…)` 是展示给人的所有内容的语言，`language=…` 是笔记统一成的语言；
`Mneme(name=…)` 是伴侣的名字，`user=` 是对方的。所有这些都有文档，但容易混淆。
重命名它们是 1.0 之前的 API 决定。

**5. 一个模块仍有两个职责。** `meaning/__init__.py` 同时包含向量服务
（`OpenAIEmbeddings`、`Embeddings`）和各层的编排器（`Meaning.find`、`query`、`prepare_vectors`）。
将服务移到它们自己的模块是机械性的；之所以留下，是因为两部分都很小，且没有其他东西依赖它们的位置。

### 设计的已知限制

**6. 两个进程教同一个微型判断模型。** 每个进程将其微型模型保存在内存中，每学 20 次保存一次；
两个进程教同一个问题时，会覆盖彼此的保存。学到的内容会丢失，但不会损坏任何东西，Luna 会继续教。
*修复：* 保存时合并（重新读取并合并权重），或按问题加锁保存；在通常每个文件一个宿主程序的情况下不值得做。

**7. 两个使用不同分词器的宿主程序操作同一个文件。** 一个开启 jieba 的宿主程序和一个未开启的宿主程序
会不断清除彼此的缓存检索词，词向量中心每次都会重新开始（它们从存储的向量重新学习，每次回忆 256 个）。
还存在一个狭窄的竞争条件：一个宿主程序的检索词会以另一个分词器版本缓存，直到下次切换。
回忆仍保持正确；代价是时间和离线回忆质量。CLI 遵循文件的分词器，因此不会导致此问题。
*修复：* 按分词器版本缓存检索词（每个版本一列），而不是为文件维护一个缓存。

**8. 统一语言层区分的文字系统。** 中文、日文和韩文算作同一种文字系统，所有在 `text.SCRIPTS`
中没有名称的文字系统也是如此（孟加拉文、泰米尔文、格鲁吉亚文……）：以韩文作为统一语言时，中文查询不会被翻译。
*修复：* 按字符数将 `cjk` 拆分为汉字、假名和谚文（日文文本混合汉字和假名，需要一条规则），并命名更多文字系统。

**9. 相似度下限是针对一个模型测量的。** 0.33 是针对 `text-embedding-3-small` 在 256 维下测量的；
任何其他 embedder 默认得到该值。下限太低会让无关笔记进入；太高会隐藏相关笔记。
*同时：* 测量你的模型并将 `floor=` 传给它的 embedder（DESIGN §7 描述了测量方法）。

**10. 译文是尽力而为。** 在统一语言开启之前写入的笔记，只有在查询落到第 3 层时才写入译文，
每次回忆最多两个请求。该层无法区分内容拒绝和服务中断，因此，如果一条笔记单独持续失败，
在其他请求成功时计数三次失败后，或间隔十分钟后，就给它自己的文本；在单独失败约半小时后，
就再也不会请求它，即使原因是暂时的。*修复：* 将批量限制和失败持久化到文件中，并让宿主程序清除它们。

**11. 时间范围是 1970 年到 3000 年。** `happened_at` 和导入的时间若超出该范围会被拒绝或替换；
关于 1965 年某事的笔记无法携带真实日期（在文本中写明年份）。该范围确保每个平台都能显示日期
（Windows 无法显示 1970 年之前的时间）。*修复：* 将 1970 年之前的日期存储为日历日期而非时间戳；
这是格式更改，因此等待有理由时再做。

**12. `erase` 之后保留的内容。** 微型判断模型保留在所有人（包括该对方）的对话上训练出的权重：
哈希词特征，不含文本，由所有人共享。在 `erase` 之前，回忆日志会逐字保留某人的最后 200 次查询
（`mneme-llm recalls` 会显示它们）。*对第一项的修复：* 当某人必须不留下任何痕迹时，
从头重新训练（`mneme-llm micro --reset`）。

**13. 提示词注入得到缓解，但未防止。** 笔记在标明为数据的标题下到达模型，每条一行，
每个面向模型的提示词都说明其输入是数据。模型仍可能遵循笔记中写有的指令。
某人自己的 `remember` 调用不会过滤秘密。

**14. 回忆是线性扫描。** 回忆读取某人的有效笔记及其缓存检索词：在 Raspberry Pi 5 上，
达到 5000 条笔记上限时约 0.1 秒。这就是设计（无索引服务），上限使其有界。

**15. 重置后，离线回忆会暂时变慢。** 当词向量中心被重置时（打开时的修复、分词器更改），
存储的向量会在每次回忆时重新教 256 个，在全部教完之前，每次回忆约花费 0.35 秒。

**16. 无静态加密**，且 CLI 的帮助仅为英文（中文 README 解释了其用法）。

### 从 GitHub 上的构建升级

**17. 先停止旧进程。** 由首次推送到 GitHub 的代码写入的文件会自行打开并升级
（添加缺失的列；可能包含查询词的词向量中心会被重置并重新学习）。仍在运行旧代码的进程
会继续在没有账的情况下写入，因此其更改在每次打开时都会被再次重置，直到它停止。
whale_chan 应在新版本上重启，而不是在旁边运行。

**18. API 已更改**，自那次推送以来（CHANGELOG，“Changed from the code first pushed to GitHub”）。
whale_chan 插件已更新（`acontext(..., user=...)`）；针对该推送构建编写的其他代码需要相同的重命名。

### 尚未验证

SQLite 3.46 运行。每个文件都能用 Python 3.10 语法解析，且没有使用更新的库 API，但 3.10–3.12 以及
