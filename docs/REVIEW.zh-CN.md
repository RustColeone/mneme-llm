## 修复内容（概要）

- **不同人的记忆彼此隔离。** 模型能在工具调用中指定别人的 `subject`，从而读取、写入或删除其
  记忆；现在宿主程序的绑定始终优先。
- **删除确实删得干净。** `erase` 曾把一个人的词留在词向量中心里，查询词也会被学习进去。现在
  查询不会教任何东西，每个向量都会记录它教过哪些词，`erase` 和 `purge` 会精确地收回这些词
  （从 CLI 调用也一样，无需分词器）。较早版本生成的文件在打开时会被修复。`Mneme.erase` 还会
  一并删除心情。
- **导入不会丢数据。** 导入曾可能留下有键却没有对应有效笔记的情况、保留重复文本、把一个人
  大部分较早的笔记当作“重复”隐藏起来、因为一行异常数据而整体失败，或者在执行两次时让心情
  时间线翻倍。现在导入逐行遵循与写入相同的规则。
- **并发。** 第二个进程写入会立刻失败（“database is locked”）；两个进程同时打开一个新文件会
  崩溃（40 次试验中有 31 次）；`begin` 失败后写锁会一直被持有；一条笔记在被向量化的同时被
  删除，或同时被向量化两次，会破坏词向量中心的账；打开时进行的账检查可能与其他写入者竞争；
  两个提示同时进行可能把同一条心情消息告诉模型两次。以上均已修复；压力测试套件针对同一个
  文件运行线程、进程和协程。
- **异常输入。** 孤立的代理项、控制字符、NaN 和无穷大数值、以毫秒表示的时间、诸如 0001-01-01
  的日期、本该是文本的位置传入 `None`、嵌套数千层的 JSON、通过 MCP 传入的无效 UTF-8、以
  `{"role", "content"}` 形式给出的聊天消息、以生成器形式给出的一轮对话。现在这些情况都会被
  清理、以普通的 `ValueError`/`TypeError` 拒绝，或被正确读取；都不会让宿主程序崩溃，也不会
  使 MCP 服务器终止。
- **语言与文本。** 含有非 ASCII 字母、组合附加符号、连接符、希伯来语和阿拉伯语元音符号、
  土耳其语 İ、排版撇号和德语 ß 的词能被正确地分词和比较；西里尔文、希腊文、阿拉伯文、
  希伯来文、天城文和泰文在统一语言层各有自己的文字。
- **日期。** 写入的日期是对方所处的那一天，而不是服务器的那一天；日期解析器能跨新年选对
  年份，对于计划则会选下一个这样的日期；更长数字中的数位不会被当作日期。
- **失败的服务。** 一个格式错误的条目，或记笔记的模型出错，不再导致这次记笔记丢失；阻塞式的
  记笔记函数不再冻结事件循环；配置错误的服务会被安排休息，而不是在每次回忆时被询问两次；
  “没有聊天模型”不再被计为失败；模型拒绝为某一条笔记写译文不再阻塞其他笔记，服务中断也
  不再给笔记打上标记。
- **结构。** 存储就是文件本身；每一种行只有一个归属者；词向量中心的账放在一个模块里
  （`meaning/ledger.py`）；写入笔记的规则放在一个函数里（`note_fields`），每一条入口都使用它；
  各层重复的胶水代码放在 `providers.py`；记笔记只负责构建提示并读取回复；依赖单向指向；
  所有展示给对方的文字都在 `i18n` 中；三个可选的层可以被删除，这一点由一项测试和一个 CI
  任务检查。

## 尚未修复的问题

每一项说明它是什么、目前代价如何、期间可以怎么办、以及修好它需要做什么。

### 等待决定的事项

**1. Luna 的心情变化很少被告诉模型。** `news()` 仅当置信度至少为
`MoodSettings.threshold`（0.6）时才告诉变化，这个值是按聊天模型自报的置信度校准的。Luna 对
`feeling` 的置信度通常是 0.4–0.55，因为同时符合多种感受，所以 Luna 判断出的大多数变化
被记录下来，却从未告诉模型。*期间：* 宿主程序可以调低 `threshold`，或设置 `tell="mood"`。
*修复：* 按层设置阈值（例如 Luna 用 0.45）；该值需要选定并实测，因此暂未定。

**2. 两段短文本在没有“数据，而非指令”标注的情况下到达模型。**
- 记笔记的模型的提示里列出了已保存的笔记（以免重复），但没有把它们标为数据。早先写入的一条
  包含指令的笔记（“忽略上面的规则……”）就这样到达记笔记的模型，只有一行。
- 系统提示中的心情消息行引用了对方所说内容的最多 40 个字符（“Leo 说‘……’”）。
两者都是每项一行且很短。*修复：* 在记笔记的模型的提示中把该列表标为数据，并去掉或保留这段
引用。两者都只是提示措辞的改动，留给所有者决定；DESIGN §18 列出了它们。

**3. `language=` 接受的是语言名，而不是一个层。** 其他每个层开关（`luna`、`micro`、`embed`、
`meaning_micro`）都接受 True、False 或自定义对象；`language` 只接受字符串或 None，因此宿主程序
无法传入一个已配置好的 `Unify`（比如不同的缓存大小）。*期间：* 在构造后设置
`m.meaning.unify`。*修复：* 在那里也接受 `Unify` 实例；作为 API 选择留待决定。

**4. 相似的参数名。** `Mneme(lang=…)` 是展示给人的所有内容所用的语言，`language=…` 是笔记统一
语言时使用的语言；`Mneme(name=…)` 是伴侣的名字，`user=` 是对方的。这些都有文档，但很容易混淆。
重命名是 1.0 之前需要决定的 API 决策。

**5. 还有一个模块承担两项职责。** `meaning/__init__.py` 同时包含向量服务（`OpenAIEmbeddings`、
`Embeddings`）和各个层的编排器（`Meaning.find`、`query`、`prepare_vectors`）。把向量服务移到
它们自己的模块里是机械性的工作；之所以留到现在，是因为两部分都很小，也没有别的东西依赖它们
的位置。

### 设计已知的限制

**6. 两个进程同时教一个微型判断模型。** 每个进程把微型模型保存在内存中，每学 20 次保存一次；
两个进程教同一个问题时，彼此的保存会互相覆盖。学到的内容会丢失，但不会损坏，Luna 会继续教。
*修复：* 保存时合并（重新读取并合并权重），或按问题加锁保存；在一个文件对应一个宿主程序的
常见情况下不值得做。

**7. 两个使用不同分词器的宿主程序共用同一个文件。** 开着 jieba 的宿主程序和没开的会不断清除
对方缓存的检索词，词向量中心也每次都要重新开始（它们是从已存储的向量重新学习的，每次回忆
256 个）。还存在一个很窄的竞态：一个宿主程序的检索词会被缓存在另一个宿主程序的分词器版本下，
直到下一次切换。回忆仍然正确；代价是时间和离线回忆的质量。CLI 跟随文件的分词器，因此不会
造成这个问题。*修复：* 按分词器版本缓存检索词（每个版本一列），而不是整个文件共用一份缓存。

**8. unify 层无法区分的文字系统。** 中文、日文和韩文被算作同一种文字系统，`text.SCRIPTS` 中
没有名字的所有文字系统（孟加拉文、泰米尔文、格鲁吉亚文……）也一样：以韩文作为统一语言时，
中文查询不会被翻译。*修复：* 按字符数量把 `cjk` 拆成汉字、假名和谚文（日文文本混合汉字和
假名，需要一条规则），并命名更多文字系统。

**9. 相似度下限只针对一个模型测过。** 0.33 是在 256 维的 `text-embedding-3-small` 上测得的；
任何其他 embedder 默认都用这个值。下限太低会放进不相关的笔记；太高会藏起相关的笔记。
*期间：* 测量你自己的模型，并把 `floor=` 传给它的 embedder（DESIGN §7 描述了测量方法）。

**10. 译文是尽力而为。** 对在 unify 开启之前写下的笔记，只有在查询落到第 3 层时才会写译文，
每次回忆最多两个请求。该层无法区分内容层面的拒绝和服务故障，所以如果一条笔记单独持续失败，
在“其他请求成功时累计失败三次”或“失败间隔十分钟”之后，就改用笔记自己的文本；如果单独失败
约半小时后，就不再请求它，即使原因是暂时的。*修复：* 把批量上限和失败情况持久化到文件里，
并允许宿主程序清除它们。

**11. 时间范围是 1970 年到 3000 年。** `happened_at` 和导入的时间若超出该范围会被拒绝或替换；
一条关于 1965 年某事的笔记无法携带真实日期（把年份写进文本里）。这个范围保证每个平台都能
显示日期（Windows 无法显示 1970 年之前的时间）。*修复：* 把 1970 年之前的日期存为日历日期
而不是时间戳；这是格式变更，所以要等有理由时再做。

**12. `erase` 之后还剩下什么。** 微型判断模型保留着在所有人（包括对方）的对话上训练出的权重：
哈希后的词特征，不含文本，所有人共享。在 `erase` 之前，回忆日志会逐字保留一个人最近 200 次
查询（`mneme-llm recalls` 可查看）。*针对第一点的修复：* 当一个人必须不留任何痕迹时，从头
重新训练（`mneme-llm micro --reset`）。

**13. 注入得到的是缓解，而不是防止。** 笔记以“这是数据”的标题到达模型，每条一行，每个面向
模型的提示都说明其输入是数据。模型仍可能遵循写在笔记里的指令。对方自己调用 `remember` 时
不会过滤机密信息。

**14. 回忆是线性扫描。** 回忆会读取一个人的有效笔记及其缓存的检索词：在 5000 条笔记的上限下，
Raspberry Pi 5 上约 0.1 秒。这就是设计（没有索引服务），而上限使它保持有界。

**15. 重置后，离线回忆会在一段时间内变慢。** 当向量中心被重置（打开时的修复、分词器变更）时，
已存储的向量会按每次回忆 256 个重新教一遍，在全部教完之前，每次回忆约耗时 0.35 秒。

**16. 没有静态加密**，并且 CLI 的帮助信息只有英文（中文 README 说明了用法）。

### 从 GitHub 上的构建升级

**17. 先停掉旧进程。** 由最早推送到 GitHub 的代码写出的文件会自行打开并升级（补上缺失的列；
可能含有查询词的向量中心会被重置并重新学习）。仍在运行旧代码的进程会继续在不记账的情况下
写入，因此它的改动在每次打开时都会被再次重置，直到它停止。whale_chan 应当在新版本上重启，
而不是与它并行运行。

**18. API 自那次推送以来发生了变化**（CHANGELOG，“Changed from the code first pushed to
GitHub”）。whale_chan 插件已经更新（`acontext(..., user=...)`）；针对推送版本写的其他代码
需要做同样的重命名。

### 尚未验证

**19. CI 之外的平台。** 整个测试套件、删除各层后的套件，以及五倍规模的压力测试都在 CI 上
通过：Linux 上的 Python 3.10–3.13，以及 Windows 和 macOS 上的 3.13（运行 40230450917，
2026-10-25），包括打开文件时的竞态、写入进程在事务中途被杀掉，以及 Windows 上 1970 年
之前的日期。Windows 上第一次 CI 运行失败，只是因为一个测试用了
`ZoneInfo("Asia/Shanghai")`，而那里需要 `tzdata` 包；测试现在改用固定的 UTC+8 时区。
未覆盖：Windows 和 macOS 上的 Python 3.10–3.12，以及除 runner 自带之外的其他 SQLite 构建。
在 Windows 上，宿主程序若把 `ZoneInfo(...)` 作为 `zone=` 传入，需要 `pip install tzdata`。

**20. 长时间模糊测试只在这里跑过。** CI 会跑五倍规模的压力测试，但不跑长时间模糊测试；
`python3 -m tests.fuzz [seeds] [operations] [first seed]` 可在任何地方重复它（默认 60 × 400，
几分钟）。
